# Branding Guidelines

## Purpose
This document defines how Starsong Tools should present itself as an ecosystem while preserving strong individual product identity.

For visual implementation standards, see the [Starsong Design System v1.1](../design-system/Starsong-Design-System-v1.1.md).

## Starsong Tools Naming
- `Starsong Tools` is the ecosystem name.
- Product names should remain the primary in-app identifier.
- The ecosystem label should support trust and consistency, not overshadow the product.

## Product Naming
- Product names should be clear, direct, and useful.
- Prefer names that communicate purpose rather than abstract branding language.
- Product naming should remain distinct from protocol, feature, or internal architecture naming.

## Attribution Standards
- When an application references Starsong Tools, it should do so as ecosystem context.
- Ecosystem attribution may appear in About dialogs, repository docs, startup/about screens, or subtle shell metadata.
- Product identity remains primary.

## About Dialog Standards
Each Starsong application should eventually provide an About surface containing:

- product name
- version
- brief purpose statement
- Starsong Tools ecosystem attribution
- relevant legal or platform notices when needed

## Footer Standards
- Footers are optional, especially in compact utility apps.
- When present, footers should be quiet and informational.
- Good footer content includes version, update state, or legal links.
- Footers should never compete with primary workflow actions.

## Ecosystem Identity Rules
- Products should feel related first and differentiated second.
- Shared typography, spacing, shell structure families, and semantic status behavior should do most of the ecosystem identity work.
- Logos, screenshots, product icons, and workflow-specific illustrations may remain product-specific.
